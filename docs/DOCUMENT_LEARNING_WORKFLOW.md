# Problems from Markdown sections — MRW 0.23.0

Use **Open Document…** for an original file or saved copy; see the
[opening workflow](READING_OUTLINE_WORKFLOW.md) for folder navigation and scope.
Open a Markdown document and choose its section in **Contents**. Use the
question icon beside that heading, its **Problems for Contents Section**
context-menu action, or the matching Contents title action. **Problems for
Document** works from the active Markdown preview or editor. An Obsidian note's
preview also has **Problems** beside Show Contents. No text selection, question
popup, source import, AI account or prerequisite list is required.

The existing study view identifies the document and named Return destination.
**Enter a problem** opens the question form. Enter the statement, select an
activity and optionally enter a reference answer. **Attribution, hints and
sources** contains their authors and origins. Application problems are the
default here. **Associate saved problem…** explicitly links a previously saved
question; it preserves that question's source references and review state.
**Find problem** searches the document's saved problem statements.

Each problem offers **Attempt** and **Review solution** together. Direct review
creates no attempt, submission, outcome or FSRS update. A missing solution has
**Attach solution**; **Correct solution** keeps earlier attributed versions.
The statement, solution, **Your attempt** and **Unresolved question** remain
separate. Display and attribution do not establish mathematical correctness.

An attempt starts with its solution and study source context concealed. If you
review a solution, MRW retains the draft and records consultation. Subsequent
submission snapshots carry that exposure. History export resolves consulted solutions through their recorded review event
and exact attributed snapshot, including older revision-only exposure markers.
Earlier immutable submissions retain
their original exposure evidence. Closing review does not erase consultation;
a later independent attempt starts with fresh work and concealed help. MRW
does not monitor other applications or infer whether displayed text was read.

**Save question** records a difficult step for later. **Copy help request for
Codex** includes the selected problem, exact associated text, attribution and
unresolved question. Clipboard handoff is optional and calls no model. Replies
use the existing explicit review/retention path. **Pause / save** checkpoints
work and review context; reopen the row in **Studies** or use **Resume Study**.

**Return to filename › section** saves work and restores the invoking heading
or exact link occurrence in Markdown preview. Live edits outside that occurrence
shift its location. Overlap, missing files or a changed revision after restart
produce a visible explanation, not a guessed location. **Open document without
exact location** remains available when the file exists. To set a new return
location, select its current Contents section and open its problems again.
Renames are not inferred. Scope and symlink checks still apply.

## Document associations and saved context

The document URI selects an existing version-2 study independently of document
revision. Each problem retains its association; incidental prose edits do not
remove problems. The invoking section's exact editor text and revision are a
study context snapshot, including unsaved text where present. No ordinary note
is written to create that snapshot. Its internal file-URI context identifier is
not an `mrw-outline` citation and grants no private-store authority. Retained
source citations keep their own source-qualified identity, immutable revision
and exact passage. Explicitly linked problems preserve their owner records;
local solution corrections retain the original and create a local revision.

The existing bounds apply: 200 question revisions and sixteen retained source
contexts per study. Opening another section does not add a retained context
until a problem actually uses it. Changed navigation pins do not change the
snapshot's original text or revision.

## Recall review and later problem work

**Keep for spaced review** explicitly admits a definition, hypothesis,
missing-step or argument question to the existing FSRS adapter. Revisions start
outside review. **Due here** offers at most the configured short-block limit,
from questions explicitly associated with this document. Dismiss the offer or
continue reading. **Due review** shows it again. Question, minute and new-item
limits remain adjustable in MRW settings. Skip, pause, retire and correction
replay retain their existing meanings.

**Keep problem for later** and **Schedule problem work** store a separate
later-work flag/date. They do not admit a recall question or run FSRS. The date
is displayed here; this increment adds no notifications or background service.
Application work, solution viewing, skipping and ordinary rereading generate no
recall grades. Optional effort reports and existing adaptation remain attached
to attempts, never inferred from dwell time.

## Short example

In a Markdown section headed **Parity**, use the problem “For a nonnegative
integer n, show that n(n+1) is even.” An attributed solution is “One of two
consecutive integers is even.” Enter the solution with author **Codex companion
(OpenAI)** and origin **AI proposal** when copying this example. It is a software
example, not a required study exercise or mathematical verification claim.

Save the problem and choose **Review solution**. Return to Parity. Reopen its
problems and choose **Attempt**, type work, then review the solution without
submitting. Pause and resume: the work, exposure and Return destination remain.
For your own reading, substitute a problem worth working on.

See [validation](DOCUMENT_LEARNING_VALIDATION.md) for automated checks, actual
host observations, package identity and observation limits. General research
resumption and compressed-argument reconstruction follow this increment.
