# MRW 0.23.42: retained justification routes

This increment makes the bounded justification engine available through
**Proofs → Justification…**. It preserves ordinary document workflows and adds
no problem registration or claim-entry form.

## Delivered interaction

Open the Euclid example, read its supplied Bézout and unique-factorization
arguments, then explicitly search under the displayed admissions. MRW retains
two checked conditional routes and their exact source snapshots. Source buttons
open those passages in the same reader; Back to routes returns to the result.
Withdrawing one admission checks a successor while keeping the earlier context
and certificates. Either result reopens after restart without another Lean run.
Return to document preserves the originating editor buffer.

Opening the view does not build a checker, run a search, admit a premise or save
a result. Local checker setup is explicit, uses the installed Lean 4.32.2
and downloads nothing. The VSIX includes pinned source assets rather than a
compiled checker. The current executable is qualified for Linux x86-64/WSL;
a different compiler output is refused. Saved results remain readable without it.
The Lean lessons independently use 4.33.0.

The existing artifact coordinator owns publication, relocation and recovery.
Results are immutable, content-addressed and bound to exact input/output,
checker identity and source snapshots. Retry recognizes an already published
request before running again. Interrupted unpublished staging is preserved
without hiding completed records. A failed managed-generation publication is
recovered through the existing journal; no partial successor is substituted.

The companion-status menu is also repaired: adding local checker setup must not
displace the status action. The two READMEs now present tasks before architecture,
introduce justification terms, explain companion ownership and identify current
limits. [Writing review](README_REVIEW_20261115.md).

## What remains awkward

The example no longer requires a repository checkout, a separate developer
script, manual JSON result storage, copying passages into another viewer or
rerunning Lean merely to reopen a result. Withdrawal and predecessor navigation
are explicit reader actions.

General context assembly from ordinary notes is still a reviewed JSON-input
route. Broader Hilbert/constant-specification search, arbitrary arithmetic proof
checking and informal paper–Lean correspondence remain separate obligations.
An empty bounded search is not a disproof. The Euclid example checks composition
under its stated admissions, not the arithmetic proofs themselves. No additional
user study is required before this delivery.
